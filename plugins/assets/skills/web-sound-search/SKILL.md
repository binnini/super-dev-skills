# 소리 현황 → 웹에서 소리 찾기 → 비교 페이지 → 결정 → 게임에 넣기

**먼저** 프로젝트의 `.claude/skill-profile.yaml`을 읽는다(형식은 이 스킬 저장소 `templates/skill-profile.yaml`). 아래 `<work_dir>` · `<python>` · `sound.*` · `docs.*`는 그 값이고, `<skill_dir>`는 이 SKILL.md가 있는 폴더다. 예시의 수치 · 이름은 10-23 TombOfTheMask 것이다.

10-23 빨판 소리를 찾던 방법을 정리한 것이다(0단계 현황 페이지는 10-24에 더함). 사용자는 소리를 귀로 고르고, Claude는 소리를 못 듣는다. 그래서 Claude가 할 일은 **후보를 넓게 모으고, 듣기 쉽게 늘어놓고, 숫자(길이 · 시작 지연 · 라이선스)로 거르는 것**까지다. "이 소리가 좋다"는 판단을 Claude가 하지 않는다.

## 0. 지금 소리 현황 · 필요한 느낌

무엇을 찾을지 사용자가 아직 정하지 않았거나 "어떤 소리가 필요해?"로 시작하면 이 단계부터. 찾을 순간이 이미 정해졌으면 1단계로 간다.

1. **필요한 느낌 초안**: `<work_dir>/sound_needs.json`(git 무시)을 쓰거나 고친다. 형식은 [scripts/build_status.py](scripts/build_status.py) 맨 위 설명. 순간마다 `want`(new · replace · check · keep), `feel`, `length`, `with`, `why`를 적는다. 근거는 `docs.rules`의 소리 장 · `docs.pending` · `vfx.role_colors`(컨셉 문서) · 사용자 말이다. 우리 소리가 없으면 `new`, 🔶 귀로 확인 대기면 `check`로 둔다. `replace`는 사용자가 말했을 때만 쓴다(Claude가 소리를 판단하지 않는다). `feel`은 사용자 말을 그대로 옮긴다.
2. **페이지 만들기**(프로젝트 루트에서):
   ```bash
   <python> <skill_dir>/scripts/build_status.py
   ```
   프로필의 `sound.slots`(순간 목록) · `sound.tuning_asset`(지금 겹) · `sound.audio_dir`의 `.meta`(파일) · `sound.labels`(순간 이름표 · 묶음 · 임시 삐 목록) · `docs.original_sounds`(원작 길이) · `docs.credits_sound`(라이선스)를 읽는다. 순간마다 상태를 하나로 정한다: 우리 소리 / 원작(스위치가 켜 있고 `sound.original_game_dir`에 파일이 있을 때) / 임시 삐 / 조용. 원작 키가 비어 있으면 원작 줄 · 버튼은 나오지 않는다. "확인:"으로 시작하는 줄(에셋에 없는 순간, 찾을 수 없는 guid)은 사용자에게 알린다. 새 순간은 `sound.labels` 파일에 이름 · 묶음을 더한다.
3. **열기 · 확인**: `sound.preview_server`로 `http://localhost:<port>/<work_dir>/sound_status.html`을 연다. `javascript_tool`로 모든 `.len`이 길이로 바뀌었는지(`파일 열기 실패` 0개), 콘솔 오류가 없는지, 화면 폭을 넘지 않는지 본다.
4. **사용자에게**: 상태별 수(우리 소리 · 원작 · 임시 삐 · 조용)와 `new`인 순간을 알린다. 페이지에서 할 수 있는 것도 설명한다: 지금 소리를 게임처럼 듣기(겹 · 늦춤 · 음높이 · 볼륨 그대로), 원작 듣기(로컬에 파일이 있을 때만), "내 판단"(새로 필요 · 바꾸고 싶음 · 귀로 확인 대기 · 그대로)과 원하는 느낌 메모, **찾을 목록 복사**.
5. **찾을 목록 받기**: 사용자가 붙여 넣은 `[소리 찾기 요청]` 글을 읽는다. 순간마다 `Id(이름): 판단 | 지금 … | 초안 느낌 … | 내 메모 … | 길이 …` 형식이다. 같은 내장 브라우저에서 골랐으면 페이지 탭에서 `localStorage.sound_status_notes`를 직접 읽는다. 사용자 메모로 `sound_needs.json`의 `feel`을 고친 뒤, 순간마다 1단계로 간다(여럿이면 4단계 목차 페이지로 묶음).

## 1. 무엇을 찾는지 정하기

대화에서 아래를 먼저 읽고, 빠진 것만 짧게 묻는다(대부분은 요청에 들어 있다).

- **순간**: 게임의 어느 때 나는 소리인가(`sound.slots`의 소리 순간 목록, 없으면 새 순간).
- **느낌 · 소리 모양**: 사용자의 말 그대로(예: "뚜두둑", "쫀득하게", "챠랑 없이 거품만").
- **길이**: 자주 나는 소리(대시 · 착지 · 점)는 0.3 s 안팎, 가끔 나는 소리(판 시작 · 괴물)는 길어도 된다. 앞 무음이 짧아야 한다(원작 출발음은 0~1프레임 안에 시작).
- **같이 날 게임 소리**: 같은 순간에 이미 나는 우리 소리(`sound.tuning_asset`의 겹, 파일은 `sound.sfx_dir`). 비교 페이지에서 같이 틀어 본다.
- **반복 겹이 필요한지**: "뚜두둑"처럼 같은 소리가 여러 번 이어지는 느낌이면 `pattern`(겹 수 · 간격 · 음높이 차)을 켠다.

## 2. 검색어 만들기

영어로 8~12개. 사이트 태그가 영어라 한국어는 거의 안 걸린다.
- 물건 · 동작(`suction cup release`, `plunger pop`), 소리 이름(`squelch`, `pop`, `thwop`), 재질(`wet`, `slime`, `sticky`), 장르 붙이기(`cartoon`, `foley`, `game`)를 섞는다.
- 비슷한 동작을 넓게(빨판 → 테이프 떼기 · 슬라임 · 물 튀김). 엉뚱해 보여도 들어 보면 맞는 것이 있다.

## 3. 사이트 훑기

내장 브라우저로 Freesound · Pixabay를 한 번 연 뒤 [references/extract.md](references/extract.md)의 코드를 `javascript_tool`로 돌린다(검색어 여러 개를 한 번에, 결과 표를 꺼내 훑음).

- 브라우저 도구 한 번은 45 s 안에 끝나야 한다(패널이 숨겨져 있으면 더 느리다). 검색어는 한 번에 3~4개씩 나눠 돌리고, 결과는 그 사이트의 `localStorage`에 모아 둔다(10-23 1묶음: 순간 6개를 이렇게 나눠 훑음).
- **여러 순간을 한꺼번에**: Freesound는 브라우저에서 고른 **id만** 꺼내 [scripts/freesound_ids.py](scripts/freesound_ids.py)로 셸에서 제목 · 올린 사람 · 길이 · 라이선스 · 미리듣기를 채운다(옮겨 적지 않아도 된다). Pixabay는 셸에서 403이라 브라우저에서 고른 것의 미리듣기 · 진짜 길이까지 읽어 짧은 배열(주소 꼬리 · 제목 · 길이 · mp3 꼬리)로 꺼낸다.

후보 고르기(사이트마다 20~25개까지):
- 순간 · 느낌과 관계없는 것(음악 신스, 청소기, UI 알림 등)은 뺀다.
- 길이는 넉넉히 받되, 한 파일에 여러 번 녹음된 긴 것(3 s 넘음)은 "잘라 써야 함"으로 남겨 둔다(쓸 부분이 들어 있을 수 있다).
- 라이선스는 거르지 않고 표시만 한다(CC0 · Pixabay = 그냥 사용, BY = 출처 표기, BY-NC = 비상업만이라 사용 전 확인). 사용자가 "출처 표기 없이 쓸 수 있는 것" 버튼으로 거른다.

## 4. 후보 파일 · 비교 페이지

후보를 `<work_dir>/<key>_candidates.json`(git 무시)에 쓴다. 형식은 [scripts/build_page.py](scripts/build_page.py) 맨 위 설명 그대로다(`key` · `title` · `purpose` · `searched` · `queries` · `pattern` · `game` · `gameLabel` · `candidates`). `game`의 경로는 페이지 기준(`<work_dir>`에서 `sound.sfx_dir`까지의 상대 경로)이고, 볼륨은 `sound.tuning_asset`의 그 순간 값을 쓴다.

```bash
<python> <skill_dir>/scripts/build_page.py <work_dir>/<key>_candidates.json
```

- `pattern`의 `rise`(반음)를 주면 반복 겹이 한 번에 그만큼 오른다 — 점처럼 이어 먹으면 음이 오르는 소리. `rise`가 없으면 `spread`로 음높이를 번갈아 흔든다(뚜두둑). 후보 파일에 `current`(지금 게임 소리) · `summary`(한 줄)를 넣으면 목차에 나온다.
- 순간이 여럿이면 목차 페이지: `build_index.py <work_dir>/<묶음>_index.html "<제목>" <work_dir>/<a>_candidates.json …` — 순간마다 후보 수 · ☆ 수 · 결정을 그 브라우저 저장소에서 읽어 보여 준다.
- 페이지는 `<work_dir>/<key>_candidates.html`(git 무시). `sound.preview_server`(저장소 루트를 여는 로컬 서버, 예: `.claude/launch.json`의 `sound-board` · 8093)를 켜고 `http://localhost:<port>/<work_dir>/<key>_candidates.html`을 연다. 게임 소리 파일을 같이 틀어야 해서 파일로 바로 열지 않고 서버로 연다.
- 미리듣기는 각 사이트에서 바로 재생한다(내려받지 않음). 페이지가 미리듣기를 브라우저에서 디코드해 **앞 무음 · 시작 뒤 최고점 · 실제 길이**와 파형을 보여 준다(두 사이트 모두 CORS 허용, 10-23 확인). 앞 무음은 넣을 때 잘라낼 수 있으니 후보를 빼는 이유가 아니다.

## 5. 확인하고 알리기

페이지 탭에서 `javascript_tool`로:
1. 모든 미리듣기가 열리는지(`new Audio(d.mp3)`의 `loadedmetadata` / `error`), 게임 소리 파일도.
2. Pixabay 길이는 목록 값이 반올림이라 진짜 길이를 재서(`extract.md` "진짜 길이 재기") 후보 파일 `dur`을 고치고 페이지를 다시 만든다.
3. 콘솔 오류가 없는지, 화면 폭을 넘지 않는지.

사용자에게는 주소, 후보 수(사이트별), 듣는 버튼 셋(한 번 · 반복 겹 · 게임 소리와 같이), ☆ · "이걸로 결정" 쓰는 법, 라이선스 주의(BY-NC, freesound_community)를 알린다. 어디서부터 들을지는 **숫자로만**(짧고 · 시작이 빠르고 · CC0) 추린다. Claude가 들어 본 것처럼 말하지 않는다.

## 6. 고른 것 · 결정 읽기

사용자가 같은 내장 브라우저에서 고르면 페이지의 `localStorage`에 남는다. 페이지 탭에서:

```js
({ stars: JSON.parse(localStorage.getItem('<key>_stars') || '[]'),
   choice: JSON.parse(localStorage.getItem('<key>_choice') || 'null') })
```

`choice`에는 고른 후보(사이트 · id · 제목 · mp3 · 라이선스)와, 반복 겹이면 그때의 간격 · 음높이 차가 들어 있다. 다른 브라우저(크롬 등)에서 골랐으면 여기서는 안 보인다(10-23 착지 · 1묶음 모두 크롬에서 골랐다). 그때는 목차 페이지의 **결정 목록 복사** 버튼을 그 브라우저에서 눌러 붙여 넣어 달라고 한다(`[소리 결정]`으로 시작하는 글, 순간마다 `key: 사이트 id "제목" {반복 겹} | ☆ …`). 목차가 없는 한 순간이면 카드 제목을 받는다. ☆만 있고 결정이 없으면, ☆ 것만 보는 버튼("☆ 고른 것")으로 좁혀 다시 들어 보고 결정해 달라고 한다.

## 7. 결정한 소리를 게임에 넣기

0. **길면 자를 곳부터**(10-23 빨판: 1.57 s 중 "뽁" 앞뒤만): 페이지 탭에서 미리듣기를 디코드해 10 ms마다 크기(dB) · 영교차(밝기 대용)를 뽑아 구조를 읽는다(쉬익 · 뽁 · 꼬리). 그다음 [assets/trim_page.html](assets/trim_page.html)을 `<work_dir>/trim.html`로 복사해 주소 뒤에 값을 붙여 연다 — `src`(미리듣기 mp3) · `title` · `key` · `cuts`("이름:시작-끝,…", 후보 3~4개) · `game`("경로*볼륨|…") · `pattern`("이름:겹수:간격:음높이차"). 사용자가 파형을 끌거나 후보를 눌러 들어 보고 "이 구간으로 결정"하면 `localStorage['<key>_trim']`에 시작 · 끝 · 페이드가 남는다. 이것도 내려받지 않고 미리듣기로만 한다.
1. **내려받기 허락**: 파일 이름 · 출처 · 크기를 말하고 허락을 받은 뒤 받는다(사이트 원본 파일. 미리듣기 mp3는 음질이 낮다 — Freesound 원본은 로그인이 필요하면 사용자에게 받아 달라고 한다).
2. **두는 곳**: 받은 원본은 `sound.source_dir`, 잘라 쓰면 ffmpeg로 만든 파일을 `sound.sfx_dir/<묶음>/`(Git LFS). 자를 때는 스펙트로그램(`showspectrumpic`)과 엔벌로프로 자를 곳을 정한다(10-23 거품: 앞 "챠랑" 금속 울림을 잘라냄).
3. **연결**: `sound.tuning_asset`의 그 순간 겹(`layers`)에 넣는다. 반복 겹이면 같은 파일을 겹 수만큼 `delay` · `pitch`를 달리해 넣는다(결정 때의 간격 · 음높이 차 그대로). 새 순간이면 `sound.slots`의 **끝에** 더하고(enum은 에셋에 순서 번호로 저장됨), 소리를 낼 코드에 `sound.play_call`을 넣는다. 자주 나는 긴 소리는 `single`, 버전이 여러 개면 `pickOne`.
4. **에디터**: 쓰기 전에 에디터 상태와 다른 세션을 확인하고(프로젝트 CLAUDE.md의 Unity CLI 규칙), 에셋 값은 eval로 쓰고 다시 읽어 확인한다. 플레이로 소리가 나는지 본다(소리 러너의 AudioSource 클립 이름).
5. **문서**: `docs.rules`의 소리 장(파일 · 처리 · 시작값 🔶), `docs.decisions` 결정 기록, `docs.pending`(귀로 확인 대기). BY 라이선스면 작성자 · 링크 · 라이선스를 `docs.credits_sound`에 적는다(없으면 만든다).
6. `sound.board`(사운드 대응표 페이지 생성기)가 있으면 다시 만들어 새 소리가 표에 나오는지 본다.
7. 현황 페이지(0단계)도 다시 만든다. `sound_needs.json`에서 그 순간을 `check`로 바꾸고, 그 순간 상태가 "우리 소리"로 나오는지 본다.
